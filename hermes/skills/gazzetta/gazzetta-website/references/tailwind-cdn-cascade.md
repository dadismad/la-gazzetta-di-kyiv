# Tailwind CDN Cascade Architecture (June 2026)

## The Architecture

The Gazzetta site is a single-page application generated by `scripts/build_frontend.py`. There is NO external CSS file — all styling lives in an inline `<style>` block inside `public/index.html`. The page also loads Tailwind via CDN:

```html
<script src="https://cdn.tailwindcss.com?plugins=forms,container-queries"></script>
<style>
  /* all our CSS rules go here */
</style>
```

## The Cascade Problem

**Tailwind CDN injects its generated styles AFTER our inline `<style>` block.** The CDN script runs asynchronously after DOM parse and appends its own `<style>` element to the document. In CSS cascade, when specificity is equal, **later rules win**. This means Tailwind CDN overrides any of our rules that target the same properties — even though our `<style>` appears first in source order.

### Verified Example (June 2026)

```css
/* Our inline <style> — rendered FIRST in HTML */
body { background: #0A0A0F; color: #E6E4E0; }
```

```css
/* Tailwind CDN injects LATER — wins by cascade */
.bg-surface { background-color: #FAF9F6; }
```

Result: `getComputedStyle(document.body).backgroundColor` returns `rgb(250, 249, 246)` — the Tailwind value, not ours. The page rendered with a cream background despite our CSS explicitly setting dark.

Similarly, `h3 { font-size: 14px !important; }` was overridden by a Tailwind CDN rule with higher specificity: `h3.font-headline-md { font-size: 11px !important; }` — Tailwind's `!important` with a compound selector beats our `!important` with a simple selector.

## The Fix Pattern

### Rule 1: Use `!important` on body, background, font-size, and color rules

```css
body { background: #0A0A0F !important; color: #E6E4E0 !important; }
.font-body-md { font-size: 13px !important; }
```

### Rule 2: Match Tailwind's specificity when Tailwind uses compound selectors

Tailwind generates `h3.font-headline-md { font-size: 11px !important; }` because Tailwind's utility classes use compound selectors. We must match:

```css
/* WRONG — specificity (0,0,1), loses to Tailwind's (0,1,1) */
h3 { font-size: 14px !important; }

/* RIGHT — specificity (0,1,1), ties Tailwind, our source order wins */
h3.font-headline-md, h3, .font-headline-md { font-size: 14px !important; }
```

### Rule 3: Never use inline `style=""` attributes as a workaround

Inline styles create maintenance debt. The body tag previously had `style="background:#0A0A0F!important"` which was removed in favor of the proper `!important` CSS rule.

### Rule 4: Verify with `getComputedStyle()` in browser console, NOT curl or snapshot

`curl` sees static HTML. `browser_snapshot` sees the accessibility tree (pre-JS state). Only `getComputedStyle()` reveals which rule actually won the cascade. After every CSS change:

```js
JSON.stringify({
  bodyBg: getComputedStyle(document.body).backgroundColor,
  bodyFont: getComputedStyle(document.body).fontSize,
  h3Size: getComputedStyle(document.querySelector('article h3.font-headline-md')).fontSize
})
```

## Non-obvious CDN Behavior

- The Tailwind CDN script at `cdn.tailwindcss.com?plugins=forms,container-queries` generates CSS on-the-fly from the classes found in the DOM. It does NOT load a pre-built stylesheet.
- Classes like `bg-surface` are NOT standard Tailwind — they're custom classes that the CDN may or may not interpret. The CDN may generate rules for them based on heuristics.
- The CDN injects a `<style>` element at the END of `<head>`, after any manually-written `<style>` blocks. This guarantees cascade victory for any non-`!important` property the CDN also targets.
