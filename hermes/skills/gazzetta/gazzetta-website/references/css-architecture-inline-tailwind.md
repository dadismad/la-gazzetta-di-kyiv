# CSS Architecture — Inline Style + Tailwind CDN

## Critical Architecture Fact

The site's CSS is **entirely inline** inside a `<style>` block within `build_frontend.py` (the Python template that generates `public/index.html`). There is NO external `styles.css` file deployed to GCS. The `public/styles.css` file exists locally but is never referenced by the HTML and never deployed.

## How Styling Actually Works

1. **Google Fonts** — Inter, Playfair Display, JetBrains Mono loaded via `<link>` in `<head>`
2. **Material Symbols** — icon font loaded via `<link>`
3. **Tailwind CDN** — `<script src="https://cdn.tailwindcss.com">` generates utility classes dynamically
4. **Inline `<style>` block** — All custom CSS rules live here (~120 lines), generated by `build_frontend.py`

## The Tailwind Cascade Problem

Tailwind CDN injects its generated stylesheet **after** the page's `<style>` block. This means Tailwind classes can override inline custom rules because:

- Equal specificity: later rule wins (Tailwind always loads last)
- Higher specificity: Tailwind class selectors (`.text-headline-md`) beat tag selectors (`h3`)

### Fix Pattern: `!important` + High-Specificity Selectors

When overriding Tailwind CDN defaults, use:
```css
/* WRONG — Tailwind CDN overrides this */
h3 { font-size: 14px; }

/* WRONG — still loses to Tailwind's .text-headline-md */
h3 { font-size: 14px !important; }

/* RIGHT — match Tailwind's class + tag specificity */
h3.font-headline-md, h3, .font-headline-md { font-size: 14px !important; }
```

### Body Background Special Case

The `<body>` tag uses `class="bg-surface"` which Tailwind CDN may or may not resolve. The body rule MUST use `!important`:
```css
body { background: #0A0A0F !important; color: #E6E4E0 !important; }
```

## Verification

- `body` computed background: must be `rgb(10, 10, 15)` (#0A0A0F)
- Card `h3` computed font-size: must be `14px`
- Body computed font-size: must be `13px`
- `.gap-score` computed font-family: must include `JetBrains Mono`
