# Gazzetta di Kyiv — File Management Architecture

## The Problem: Root/Site Duplication

The project suffers from a systemic file duplication issue where 17 HTML/JS/CSS files exist in BOTH the project root AND `site/`:

```
gazzetta-di-kyiv/
├── app.js          ← EDIT TARGET (what I modify)
├── styles.css      ← EDIT TARGET
├── index.html      ← EDIT TARGET
├── ...
├── site/
│   ├── app.js      ← DEPLOY TARGET (what goes to GCS)
│   ├── styles.css  ← DEPLOY TARGET
│   └── index.html  ← DEPLOY TARGET
```

**Critical rule:** After ANY edit to root files, copy them to `site/` before deploying:

```bash
cp app.js site/app.js && cp styles.css site/styles.css && cp index.html site/index.html
```

The cron auto-deployer (`gazzetta_deploy_to_gcs.sh`, runs every 15min via `~/.hermes/scripts/`) syncs `site/` → GCS bucket. Editing root without copying to `site/` means changes never reach production.

## Data Directory: Two Realities

```
data/                    ← SOURCE OF TRUTH (editorial content)
├── stories.json         ← 23 stories, 16 with capital_flow dicts (RICH)
├── flows.json           ← STALE (Jun 5) — DO NOT USE
├── living_stories.json
├── [43 operational JSONs that don't belong here]
└── ...

site/data/               ← DEPLOY ARTIFACTS
├── stories.json         ← COPIED from data/stories.json
├── flows.json           ← GENERATED by generate_flows.py (CURRENT)
└── ...
```

**Rules:**
- `data/stories.json` is the canonical editorial source
- `site/data/flows.json` is the canonical flows source (generated)
- `data/flows.json` is stale and should be deleted or synced
- `generate_flows.py` reads from `DATA_SOURCE / "stories.json"` = `data/stories.json`
- After any change to `data/stories.json`, copy to `site/data/stories.json`

## Script Locations (Triple)

1. `scripts/` (39 files, 5821 LOC) — canonical scripts in the project repo
2. `ops/` (34 files, 1212 LOC) — operational scripts, some overlap with scripts/
3. `~/.hermes/scripts/gazzetta_*` (20 files) — copies that cron jobs reference

**Cron jobs reference `~/.hermes/scripts/gazzetta_*`** — these are the versions that actually run. When editing a script that a cron job uses, edit the `~/.hermes/scripts/` version.

## Deploy Pipeline

```
1. Edit files at project root
2. Copy to site/: cp app.js site/app.js && cp styles.css site/styles.css
3. Generate data: python3 scripts/generate_flows.py
4. Copy data: cp data/stories.json site/data/stories.json
5. Deploy: bash ~/.hermes/scripts/gazzetta_deploy_to_gcs.sh
   (or wait for 15min cron auto-deploy)
6. Verify: curl -sk https://www.lagazzettadikyiv.com/data/flows.json
```

## Fixes Applied (June 2026)

### generate_flows.py
- **Data source:** Changed from `SITE_DATA / "stories.json"` to `DATA_SOURCE / "stories.json"`
- **Direction normalization:** Added `normalize_direction()` to handle multi-word direction strings
- **Denomination parsing:** Word-boundary regex instead of substring matching
- **Flow limit:** Increased from 10 to 12 with quality sorting
- **Headline generation:** Uses rich claim text instead of generic "$XB flowing into/out of sector"

### app.js
- **heroStoryCount:** Removed overwrite in `updateMastheadFlows()`
- **cf-hints:** Added sector short names (`$37.2B ↑ gold`)
- **positionLabel():** Deterministic per-flow variant labels
- **Direction detection:** Handle multi-word direction strings in cf-hint rendering
