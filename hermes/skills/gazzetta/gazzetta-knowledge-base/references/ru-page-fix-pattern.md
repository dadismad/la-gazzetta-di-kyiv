# RU Page Recovery Playbook

Diagnosed June 2026 when the Russian homepage (`/ru/`) showed 0 cards, 0 data, English UI despite i18n_ru.json having full translations.

## Symptoms
- Visiting `/ru/` shows English nav, English hero, English content
- `window.i18n.lang` → "en" (not "ru")
- `document.querySelectorAll('.card').length` → 0
- `window.CAPITAL_FLOWS_DATA` → undefined
- Hero indicators all show "—" (no numbers)
- Sidebar: empty generics, no ticker data

## Root Cause: Three Stacked Bugs

### Bug 1: i18n ignores URL path
`i18n.js` `detectLang()` only checks:
1. localStorage `gazzetta_lang`
2. `navigator.language`
3. Defaults to "en"

It does NOT check `window.location.pathname`. Visiting `/ru/` without prior RU usage means both localStorage and browser language default to "en".

**Fix (i18n.js line 14-20):**
```javascript
function detectLang() {
    // Path-based detection: /ru/ or /ru prefix = Russian
    if (window.location.pathname.match(/^\/ru(?:\/|$)/i)) return 'ru';
    const stored = localStorage.getItem(STORAGE_KEY);
    if (stored && SUPPORTED.includes(stored)) return stored;
    const browser = (navigator.language || '').split('-')[0];
    if (browser === 'ru') return 'ru';
    return 'en';
}
```

### Bug 2: ru_sync_gate runs before hash stage
`shipit.sh` Stage 2.6 (ru_sync_gate) copies `site/index.html` → `site/ru/index.html` BEFORE Stage 3 (build_hashed_assets). The copied file has OLD script references (`i18n.041121bb.js`). Stage 3 only updates EN index.html with new hashes. Result: RU page loads stale i18n.js without the path detection fix.

**Fix:** Move ru_sync_gate to AFTER hash stage (Stage 3.1):
```bash
# Stage 3: hash assets
build_hashed_assets.py
# Stage 3.1: ru_sync_gate — NOW copies index.html with correct hashes
for f in about.html ... index.html ...; do
    cp "site/$f" "site/ru/$f"
done
```

### Bug 3: Relative paths resolve under /ru/
All page assets use relative paths (`./i18n.xxx.js`, `./data/flow_nodes.json`, `./i18n_ru.json`). From `/ru/`, these resolve to `/ru/i18n.xxx.js`, `/ru/data/flow_nodes.json`, `/ru/i18n_ru.json` — none of which exist on GCS.

**Fix:** Deploy assets to both `/` and `/ru/`:
```bash
# Copy all hashed JS/CSS to /ru/
gsutil cp site/ru/i18n.*.js site/ru/app.*.js site/ru/styles.*.css gs://BUCKET/ru/
# Copy i18n_ru.json
gsutil cp site/ru/i18n_ru.json gs://BUCKET/ru/i18n_ru.json
# Copy data files for RU-specific data paths
gsutil -m rsync -d site/ru/data/ gs://BUCKET/ru/data/
```

## RU Data Synchronization

### flows_ru.json
RU flows have flat 1.0 pace because RU stories were translated AFTER the pace diversity fix. Flows are language-independent — same data serves both.

**Quick fix:** Copy EN flows.json to flows_ru.json:
```bash
curl -s https://www.lagazzettadikyiv.com/data/flows.json | \
  gsutil cp - gs://BUCKET/data/flows_ru.json
```

Also deploy to /ru/data/ for the relative-path case:
```bash
gsutil cp gs://BUCKET/data/flows_ru.json gs://BUCKET/ru/data/flows_ru.json
```

### stories_ru.json
Has 82 stories vs 58 EN. Generated by `translate_content.py`. Must exist at both `/data/stories_ru.json` and `/ru/data/stories_ru.json`.

### Bug 4: Unhashed script refs + missing /ru/ assets (June 2026)
When switching from hashed to unhashed script references (`app.2d0b5f18.js` → `app.js`), the `/ru/` directory contained NONE of the JS/CSS/data files. The `/ru/` page loaded `./app.js` → resolved to `/ru/app.js` → 404. Only `/ru/index.html` and static pages existed on GCS.

**Symptoms:** Hero all dashes, content English, 0 teasers. Console: `app` undefined, only 2 scripts loading (both stale hashed versions).

**Fix:** Explicitly deploy JS, CSS, i18n, and data files to `/ru/`:
```bash
mkdir -p site/ru/data
cp app.js i18n.js styles.css site/ru/
cp i18n_ru.json site/ru/
cp data/stories.json site/ru/data/
cp data/flows_ru.json site/ru/data/
gsutil -m rsync -d -r site/ru/ gs://BUCKET/ru/
```

**Key insight:** The `ru_sync_gate` in `shipit.sh` only copies HTML pages — it does NOT copy JS, CSS, or data files. Those must be deployed separately. When using unhashed refs, this is manual. When using hashed refs, the hash stage deploys them.

### Bug 5: `/ru/` index.html has its own stale hashed refs (separate from root)
The `ru_sync_gate` copies `site/index.html` → `site/ru/index.html` at shipit time. If you fix root `index.html` but don't re-run `ru_sync_gate` (or manually copy), the RU index keeps the old hashed references. **Must fix BOTH** root and `/ru/` index.html after any script ref change.

### Bug 6: `stories_ru.json` gap — i18n suffix breaks data loading (June 2026)
`getDataPath()` appends `_ru` suffix when `i18n.lang === 'ru'`: `DATA_BASE = './data/stories'` → becomes `./data/stories_ru.json`. From the RU page this resolves to `/ru/data/stories_ru.json`. If only `stories.json` exists in that directory, the RU page loads 0 stories — teaser count zero or very low.

**Symptoms:** RU teasers: 11-13 (vs EN: 33+). Story label shows "—". Console: `fetch('/ru/data/stories_ru.json')` → 404 while `fetch('/ru/data/stories.json')` → 200.

**Fix:** Copy `stories.json` as `stories_ru.json` in `/ru/data/`:
```bash
cp data/stories.json site/ru/data/stories_ru.json
gsutil cp site/ru/data/stories_ru.json gs://BUCKET/ru/data/stories_ru.json
```

**Key insight:** The `_ru` suffix in `getDataPath()` means the RU page needs BOTH `stories.json` AND `stories_ru.json` in `/ru/data/`. The same pattern applies to any data file loaded via `getJSON(getDataPath(), ...)`.
- After any deploy, verify RU page: `curl -sI https://www.lagazzettadikyiv.com/ru/` → 200
- RU must have its own copies of ALL runtime assets: `ls site/ru/i18n.*.js site/ru/app.*.js site/ru/styles.*.css site/ru/i18n_ru.json`
- `/ru/data/` must exist with stories.json and flows_ru.json: `ls site/ru/data/`
- After script ref changes, verify both EN and RU index.html have matching refs: `grep 'script src' site/index.html site/ru/index.html`
