# Data Schema: i18n System

> Internationalization architecture for bilingual (EN/RU) site.

## Files

| File | Purpose | Format |
|------|---------|--------|
| site/i18n_ru.json | Russian translations for all UI strings | JSON object: key -> string |
| site/i18n.js | Language detection and translation runtime | JavaScript module |
| site/data/stories_ru.json | Russian translations of story content | Same schema as stories.json |
| site/data/flows_ru.json | Russian translations of flow content | Same schema as flows.json |

## i18n_ru.json Keys

The translations file contains approximately 80+ keys covering:
- Site title, description, tagline
- Navigation labels
- Section headers and descriptions
- Flow labels (inflow, outflow, projected)
- Story status labels
- Sector names
- Tension and confidence labels
- Positioning labels
- UI action text (share, copy, back)
- Loading states
- Severity labels
- All keys in i18n.js getDataPath() reference

## i18n.js Runtime

```javascript
// Language detection: checks URL for /ru/ prefix
// Sets window.i18n.lang to 'en' or 'ru'
// getDataPath() returns stories_ru.json or stories.json
// getFlowsPath() returns flows_ru.json or flows.json
```

## Implementation Pattern

1. i18n.js detects language from URL
2. app.js uses getDataPath()/getFlowsPath() to fetch correct data
3. All UI text uses window.i18n[key] translations
4. Data content (headlines, bodies) lives in _ru files
